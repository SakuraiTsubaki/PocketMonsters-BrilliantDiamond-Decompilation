## Required unresolved inventory

- exact 1.0.0 cartridge/build identity and hashes;
- physical game-card revisions and later prints containing updated data;
- Brilliant Diamond Title/content/update identifiers with provenance;
- regional binary/content identity relationships;
- exact per-version asset/AssetBundle/IL2CPP/metadata changes;
- features absent from 1.0.0 but present in 1.1.0+;
- Union Room/Colosseum/GMStation behavior by version;
- cross-save Arceus event flags/data in 1.3.0;
- local communication compatibility matrix;
- version-specific glitches, fixes and data-table changes.

## Recording rules

1. Preserve 1.0.0 and every update as separate historical states.
2. Do not describe a feature as launch-content if official evidence says it arrived through update data.
3. Keep Brilliant Diamond data separate from Shining Pearl where branches/tables/assets differ.
4. Prefer hashes and provenance-bearing identifiers when they become available.
5. Do not commit retail game images or console keys.
